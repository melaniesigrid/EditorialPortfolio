Windward

A report card for investment portfolios. You say what you own, and it grades you A to F on five measures against fifteen years of real market history — then explains, in plain English, why.

melaniesigrid/windward
Hosted
Not deployed. There is a Docker Compose stack and CI, but no hosting configuration — so this one runs on your machine.

Three processes have to be up at once, which is exactly the cost of the architecture: the split that keeps maths out of the API is also the split that makes it three things to start.

How to sign in

  1. Bring up Postgres: docker compose -f infra/docker-compose.yml up -d db.
  2. Start the engine on port 8000, then the Rails API on 3000, then the web app on 5173. The README has the three commands.
  3. bin/rails db:setup seeds a demo account — demo@windward.test — with a portfolio already in it, so there is something to grade on the first screen.
  4. Sign in with that email and password. Unlike the other projects here this one does have passwords: they are hashed with bcrypt, and the session is a signed JWT issued by the Rails API.

How it works

01

You list what you own

Type in your investments and how much of each you hold. That is the whole input.

02

The maths runs

It compares you against a simple index fund over fifteen years of real market history.

03

You get a grade

A letter grade per category, plus what is dragging you down and by how much.

The grade is the easy part. The hard part is being able to defend it months later — which is why every run is stored rather than recalculated on demand.

Key achievements

  • 01 The whole thing, alone — database design, the API, the maths, the website, the tests, and the container and CI setup.
  • 02 Enforced a boundary across three languages. Rails owns auth and persistence and does no arithmetic; the Python engine does the arithmetic and is stateless. Each half can be reasoned about, and tested, without the other.
  • 03 Connected five market-data providers behind one shared interface, so the app can get real share prices and swapping a provider is a configuration change rather than a rewrite.
  • 04 Made it remember its own answers. The same question is never calculated twice, and any number shown to a user months ago can still be looked up and explained.
  • 05 Wrote 654 automated tests across RSpec, pytest and Vitest that run on every change, so a mistake in the maths gets caught before anyone sees a wrong number.
