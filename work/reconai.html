ReconAI

A supplier sends a bill. ReconAI checks it against what was actually ordered — every line, every sum — and returns approve, hold or reject, with each disagreement named and priced.

How to sign in

You don't. There is no account, no password and no database — which is the honest design for a tool that handles other companies' invoices. Nothing about your documents is stored anywhere after the page closes.

  1. Clone the repository and run npm install.
  2. Copy .env.example to .env.local and put an Anthropic API key in it.
  3. Run npm run dev and open localhost:3000.
  4. Want to see it work without a key at all? Press Preview sample output. That runs the real reconciliation engine in your browser against a built-in invoice with five deliberate errors in it — the same code path, with the AI's matching step pre-supplied.

How it works

01

Read the bill

Claude transcribes every line exactly as printed — deliberately without correcting anything that looks wrong.

02

Pair up the lines

"Wheel stops – replace" and "Wheel stop replacement" are the same job. Matching that is the one thing the AI is trusted with.

03

Redo every sum

Plain code recalculates the arithmetic, totals the overbilling and returns the verdict. No model touches any number.

This is exactly the job an accounts-payable clerk does by hand: does this bill match what we ordered, and is it safe to pay?

What it catches

PRICE

  • Charged more per unit than the order allows

QTY

  • Billed for more than was ordered

MATH

  • Quantity × price does not equal the line total

UNEXPECTED

  • A charge that is on no order at all

UNBILLED

  • Something ordered that was never billed

SUBTOTAL · TAX · TOTAL

  • The document does not foot: lines, tax and total disagree

A line can be wrong in two ways at once — mispriced and miscalculated — and the money must still be counted once. Overbilling is measured per line as billed minus authorised, never as the sum of the individual complaints. There is a regression test for exactly that.

Key achievements

  • 01 All of it — the interface, the two model calls, the audit engine, the prompts, the sample data and the tests.
  • 02 Worked out where the model belongs. Doing the matching without an LLM fails on real documents; doing the arithmetic with one fails on real money. The system uses each for the half it is actually good at.
  • 03 Stopped the model from being helpful. Early prompts quietly "fixed" a line where the arithmetic did not work — erasing the very error the tool exists to find. The transcription step now forbids recomputation: copy what is printed, do not correct it.
  • 04 Made it demonstrable with the AI switched off. Because the deciding half is a pure function, the sample run is not a canned screenshot — it is the real engine, executing.
